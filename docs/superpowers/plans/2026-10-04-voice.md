# voice · plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** publicar `voice`, el segundo plugin del marketplace `biomas`, con cinco comandos
(`/lead`, `/brief`, `/outline`, `/draft`, `/deliver`), dos subagentes propios, ocho guías
compartidas con backbone y un script que comprueba que toda sigla se explica.

**Architecture:** todo se escribe en `core/` y `scripts/sync.mjs` lo genera (decisión de
arquitectura ADR-0001; un ADR, *architecture decision record*, es el registro de una decisión, y
los de este repo están en `docs/adr/`). `sync.mjs` pasa de generar un paquete a generar varios:
cada comando, guía, agente y script declara a qué paquetes pertenece, y cada paquete declara para
qué herramientas se genera (backbone para Claude Code y OpenCode; voice solo para Claude Code).

**Tech Stack:** Node 20 sin dependencias (scripts `.mjs`), markdown con frontmatter YAML para
comandos, guías y agentes, `pandoc` en la máquina del usuario para exportar (opcional, con
degradación).

**Spec:** `docs/superpowers/specs/2026-10-04-voice-design.md`. Léela antes de cada tarea: este plan
dice cómo, la spec dice qué y por qué.

## Global Constraints

- Se edita solo `core/` y `scripts/`; lo de `plugins/*/claude/` y `plugins/*/opencode/` es
  generado, salvo `hooks/`, `evals/` y `.claude-plugin/plugin.json` (regla
  `.claude/rules/editar-solo-core.md`). Tras cada cambio en `core/`: `node scripts/sync.mjs` y
  commitear también lo regenerado.
- **Lo que hoy genera backbone no cambia ni un byte** por la fontanería de las tareas 1 y 2.
  Comprobación: `git status --porcelain -- plugins/backbone` vacío tras `node scripts/sync.mjs`.
- Nombres de comando en inglés; descripciones y todo el texto, en español.
- Las `description` del frontmatter van entrecomilladas (ADR-0002); las de guías empiezan por
  «Úsala» y tienen como mucho 500 caracteres.
- Todo comando lleva una sección `## Banderas rojas (no te las saltes)` con tabla
  `| Pensamiento | Realidad |`.
- Los agentes de solo lectura tienen exactamente `tools: Read, Grep, Glob`.
- El texto que escribe voice cumple la regla de texto autocontenido de la spec (§6): referencias
  que se entienden sin abrir la fuente y siglas explicadas la primera vez. Este plan también.
- Suite sin gastar sesiones de modelo, antes de cada commit:
  `for f in scripts/check-*.mjs; do [ "$(basename $f)" = check-activation.mjs ] || node "$f" || echo "FALLA $f"; done`
- Commits con el pie `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisiones tomadas al escribir el plan

Puntos que la spec dejaba abiertos o que la lectura del código obligó a concretar:

1. **Referencias entre paquetes.** Tres guías compartidas enlazan con guías que solo existen en
   backbone (`diagramas` → `arquitectura`; `evidencia-y-preguntas` → `depuracion-sistematica`;
   `usabilidad-accesibilidad` → `calidad-producto`). Dentro de una **guía**, una referencia a una
   guía que no está en el paquete se escribe como «`arquitectura` (guía de backbone, no incluida en
   este plugin)». Dentro de un **comando o agente**, la misma referencia hace fallar la generación:
   ahí es un error de quien escribe.
2. **El script de siglas se llama `core/scripts/siglas.mjs`**, no `check-siglas.mjs` como dice la
   spec. En este repo `scripts/check-*.mjs` son las pruebas del mantenedor, y el script que viaja
   al usuario lleva nombre de función (`suelo-calidad.mjs` se prueba con `scripts/check-suelo.mjs`).
   Su prueba es `scripts/check-siglas.mjs`.
3. **Versiones.** voice empieza en `0.1.0` y lleva su propia versión en su `plugin.json`, en su
   entrada de `marketplace.json` y en `plugins/voice/CHANGELOG.md`. Las etiquetas git `vX.Y.Z` y el
   `ref` de `examples/repo-settings.json` siguen siendo de backbone. `bump-version.mjs` gana
   `--plugin voice` (por defecto backbone).
4. **ClickUp en voice.** voice no trae su propio servidor MCP (*Model Context Protocol*, el
   mecanismo por el que Claude Code habla con ClickUp): dos plugins registrando un servidor
   `clickup` chocarían. Si backbone u otro plugin lo tiene instalado, voice lo usa; si no, degrada.
5. **Exportar.** `/deliver` usa `pandoc` si está instalado: `.docx` y `.pptx` directos, PDF solo si
   `pandoc` encuentra un motor de PDF. Si no hay `pandoc`, o falta el motor, lo dice y deja el
   markdown firmado en `salida/vN/` para que el usuario lo convierta. Docs o Slides, con el conector
   de documentos que haya en la sesión; si no hay ninguno, lo dice.
6. **Enrutado.** `check-routing.mjs` mide guías, no comandos. voice no añade guías nuevas salvo
   `veracidad-tecnica` (tarea 11), así que su corpus de enrutado se escribe en esa tarea, si la guía
   llega a existir.

2. Justo antes de `let written = 0;` sustituye esa línea por:

```js
// Toda escritura pasa por emit(): así sync.mjs sabe qué ha generado en esta pasada y, al
// final, puede borrar lo que hay en sus directorios y ya no sale de core/. Sin esto, un
// comando retirado deja su fichero generado para siempre y sync-check no lo ve, porque solo

let written = 0;
const generated = new Set();

}
```

```js
// ---------------------------------------------------------------------------
// Poda: lo que hay en un directorio poseído y no se ha generado en esta pasada es un
// huérfano de algo que salió de core/. Solo se poda dentro de managedDirs: hooks/, evals/ y
// el manifiesto se editan a mano y quedan fuera por construcción.
// ---------------------------------------------------------------------------
function prune(dir) {
  if (!existsSync(dir)) return 0;
  let removed = 0;
  for (const entry of readdirSync(dir)) {
    const p = resolve(join(dir, entry));
    if (statSync(p).isDirectory()) {
      removed += prune(p);
      if (readdirSync(p).length === 0) rmSync(p, { recursive: true });
    } else if (!generated.has(p)) {
      rmSync(p);
      removed++;
    }
  }
  return removed;
}
let pruned = 0;
for (const A of Object.values(ADAPTERS)) for (const d of A.managedDirs) pruned += prune(d);
```

- [ ] **Step 5: `substitute` sabe de paquetes**

Sustituye la función por:

```js
function substitute(text, A, pkg, { strict }) {
  const conSnippets = text.replace(/^\{\{snippet:([a-z-]+)\}\}$/gm, (_, name) => snippet(name));
  const suelto = /\{\{snippet:([a-z-]+)\}\}/.exec(conSnippets);
  if (suelto) {
    throw new Error(
      "Token {{snippet:" + suelto[1] + "}} mal colocado: va solo en su línea y sin sangrar.",
    );
  }
  return conSnippets
    .replace(/\{\{guide:([a-z-]+)\}\}/g, (_, name) => {
      if (!GUIDES[name]) throw new Error("Guía desconocida en token: " + name);
      if (pkgsOf(GUIDES[name]).includes(pkg)) return A.guideRef(name);
      // Un comando o un agente de este paquete no puede depender de una guía que no viaja con
      // él: es un error de quien lo escribe. Una guía compartida sí puede mencionarla.
      if (strict) throw new Error(`La guía ${name} no está en el paquete ${pkg}`);
      return A.foreignGuideRef(name, pkgsOf(GUIDES[name])[0]);
    })
    .replace(/\{\{script:([a-z-]+)\}\}/g, (_, name) => {
      if (!SCRIPTS[name]) throw new Error("Script desconocido en token: " + name);
      if (!pkgsOf(SCRIPTS[name]).includes(pkg)) {
        throw new Error(`El script ${name} no está en el paquete ${pkg}`);
      }
      return A.scriptRef(name);
    })
    .replace(/\{\{template:([A-Za-z.-]+)\}\}/g, (_, name) => {
      if (!TEMPLATES.includes(name)) throw new Error("Plantilla desconocida en token: " + name);
      if (pkg !== "backbone") throw new Error(`Las plantillas solo existen en backbone`);
      return A.templateRef(name);
    });
}
```

Reglas del detector (las que prueba el paso 1):
- **Sigla**: palabra de dos o más caracteres que empieza por letra mayúscula y solo tiene
  mayúsculas o dígitos (`ERP`, `API`, `ISO25010`). Se acepta una `s` final de plural (`APIs`) y se
  normaliza quitándola.
- **Explicada**: en la línea de su primera aparición hay `SIGLA (` seguido de texto y `)`, o texto
  seguido de `(SIGLA)`.
- **El glosario no cuenta**: la primera aparición tiene que explicarse donde aparece.
- **Se ignora** lo que hay dentro de bloques de código (entre líneas de tres comillas invertidas),

  listadas en un comentario `<!-- siglas-ignorar: iOS, SKU -->`. Esa lista la decide el usuario

- **`--diapositivas`**: el documento se parte por líneas que son solo `---`, y la regla se aplica

```js
#!/usr/bin/env node
/**
 * siglas.mjs — avisa de las siglas que no se explican la primera vez que aparecen.
 *
 * Viaja dentro del plugin voice y lo ejecuta /deliver antes de pedir la firma. Es código y no
 * prosa porque «toda sigla explicada» es comprobable de forma determinista, y un agente que lo
 * comprueba a ojo se salta las que ya conoce: justo las que el lector de fuera no conoce.
 *
 * Lo que avisa lo decide el usuario: una marca o un código de producto no es una sigla. Para
 * eso, `<!-- siglas-ignorar: A, B -->` en el propio documento.
 *
 * Uso:    node siglas.mjs <fichero.md> [--diapositivas]
 * Salida: JSON en stdout. 0 sin avisos · 1 hay siglas sin explicar · 2 no se pudo leer.
 */
import { readFileSync } from "node:fs";

const [fichero, ...flags] = process.argv.slice(2);
const diapositivas = flags.includes("--diapositivas");
let texto;
try {
  texto = readFileSync(fichero, "utf8");
} catch (e) {
  console.error("siglas: no se pudo leer " + fichero + ": " + e.message);
  process.exit(2);
}

const ignoradas = new Set();
for (const m of texto.matchAll(/<!--\s*siglas-ignorar:\s*([^>]*?)\s*-->/g)) {
  for (const s of m[1].split(",")) ignoradas.add(s.trim().replace(/s$/, ""));
}

// Quita lo que no es prosa, conservando los saltos de línea para que los números de línea
// sigan siendo los del fichero.
function limpiar(t) {
  const blanco = (s) => s.replace(/[^\n]/g, " ");
  return t
    .replace(/```[\s\S]*?```/g, blanco)
    .replace(/<!--[\s\S]*?-->/g, blanco)
    .replace(/`[^`\n]*`/g, blanco)
    .replace(/https?:\/\/\S+/g, blanco);
}

const SIGLA = /\b([A-ZÁÉÍÓÚÑ][A-ZÁÉÍÓÚÑ0-9]+)(s?)\b/g;
const esc = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

function explicadaEn(linea, sigla) {
  const s = esc(sigla);
  return new RegExp(`\\b${s}s?\\s*\\([^)]+\\)`).test(linea) ||
    new RegExp(`\\S[^()]*\\(${s}s?\\)`).test(linea);
}

function revisar(parte, lineaInicial, diapositiva) {
  const vistas = new Set();
  const avisos = [];
  parte.split("\n").forEach((linea, i) => {
    for (const m of linea.matchAll(SIGLA)) {
      const sigla = m[1];
      if (vistas.has(sigla) || ignoradas.has(sigla)) continue;
      vistas.add(sigla);
      if (!explicadaEn(linea, sigla)) {
        avisos.push({ sigla, linea: lineaInicial + i, diapositiva });
      }
    }
  });
  return avisos;
}

const limpio = limpiar(texto);
let sinExplicar;
if (diapositivas) {
  sinExplicar = [];
  let linea = 1;
  limpio.split(/^---$/m).forEach((parte, n) => {
    sinExplicar.push(...revisar(parte, linea, n + 1));
    linea += parte.split("\n").length - 1;
  });
} else {
  sinExplicar = revisar(limpio, 1, null);
}

console.log(JSON.stringify({ fichero, sinExplicar }, null, 2));
process.exit(sinExplicar.length ? 1 : 0);
```
